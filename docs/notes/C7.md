# C7 design note: Telegram formatting, approvals and the switchboard

- The orchestrator (a Claude Code session with the official Telegram plugin) still sends its own replies through the
  plugin's `reply` tool. bin/chat builds what it should send (`status --card`, `agents`) and does the parts that must
  not depend on the model: the owner check, the `/to` routing through bin/notify, the approval record and the
  forwarding of agent events (which must reach the chat while the session is idle).
- Forwarding sends through the Bot API directly (`sendMessage` only; the plugin keeps polling), from a loop bin/chat
  start runs beside the session. The plugin has no API for another process to send through.
- Buttons: the plugin renders inline buttons only for Claude Code permission prompts and ignores other callback data,
  so a button bin/chat sent could not be answered. Telegram therefore gets numbered replies for other approvals; the
  button payload exists for a channel that can route callbacks (`channel_buttons` = `all`).
